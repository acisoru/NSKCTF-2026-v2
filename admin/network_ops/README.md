# Сетевая смена | Easy, Medium, Hard | ADMIN

## Информация

> Периметр цел. Связи внутри нет.
> После карантина лаборатории нужна сетевая смена: восстановить рабочие места,
> разделить контуры и проверить резерв. ALICE принимает только измеримый результат.
>
> http://<ip>:3388

Один сервис содержит три независимых задания для CTF-платформы:

| Задание | Сложность | Вход |
|---|---|---|
| Нет линка | Easy | `/?level=easy` |
| Линк есть. Сети нет. | Medium | `/?level=medium` |
| Резерв только на схеме | Hard | `/?level=hard` |

## Деплой

Исходники для разработки находятся в `src/`. Каталог `deploy/` содержит
копию `src/`, Dockerfile, Compose-файлы и `.env`; он собирается автономно.
После изменения исходников выполните `./deploy/sync-src.sh` из каталога
задачи, затем запускайте Compose из `deploy/`.

Из корня репозитория:

```sh
cd admin/network_ops/deploy
docker compose up
```

Локальная игра: http://localhost:3388. Для фона: `docker compose up -d`.
На хосте нужны Docker Engine с Compose, Linux либо Docker Desktop; Node.js и
Python устанавливать не нужно. Сборка выполняется автоматически при `up`.
В первый раз Docker скачивает зависимости, включая Open vSwitch и FRRouting.
Перед публикацией можно создать `.env` из `.env.example` и заменить три флага
и `PUBLIC_ORIGIN` на публичный HTTPS origin. Не публиковать `.env` и исходники.

Вход обязателен через Yandex OAuth. В `.env` задать `YANDEX_CLIENT_ID` и
`YANDEX_CLIENT_SECRET`; право приложения: `login:info`. Для локального запуска
Redirect URI: **`http://localhost:3388/auth/yandex/callback`**. Схема, хост и порт
должны точно совпадать с настройками Яндекса и `PUBLIC_ORIGIN`. Отсутствие ключей
не включает анонимный режим: сервер закрывает доступ к игровой сессии.
Compose публикует обычный HTTP на 3388, без встроенного TLS-прокси. Для публичного
HTTPS origin нужен внешний reverse proxy с сертификатом; направить его на HTTP
порт приложения, сохранив исходный Host. HTTP разрешён для loopback-разработки.

Сервисы:

- `network_ops`: непривилегированный Node.js, статический 3D-клиент, личные
  сохранения, серверные состояния монтажа, консоль LabOS и очередь проверок.
- `network_checker`: Linux network namespaces, Open vSwitch с userspace datapath,
  FRRouting, DHCP/DNS, nftables и реальные сетевые пробы. Один активный стенд.
- `network_secrets`: одноразовое создание случайного секрета взаимодействия.
  Секрет хранится в отдельном volume и не передаётся браузеру.

**Важно:** checker запускается с `privileged: true`, поскольку создаёт сетевые
пространства имён и виртуальные интерфейсы. Docker socket, сеть хоста и файлы
хоста ему не подключаются, но privileged-контейнер не является достаточной
границей безопасности от хоста. Локальный Compose предназначен для разработки
в Docker Desktop или отдельной тестовой VM. На турнире checker следует вынести
на выделенную VM, не содержащую CTF-платформу, секреты других задач или данные
организаторов. Не публиковать порт checker в Интернет.

### Отдельный Worker

На выделенной машине создать `.env` с сильным случайным `CHECKER_TOKEN`,
`CHECKER_BIND` равным приватному адресу интерфейса WireGuard, например
`10.66.0.2`, и `CHECKER_PORT=9134`, затем из `deploy/`:

```sh
docker compose -f runner.compose.yml up -d
```

На игровой машине задать OAuth-клиент, тот же `CHECKER_TOKEN`, `PUBLIC_ORIGIN` и
`CHECKER_URLS=http://10.66.0.2:9134`, затем:

```sh
docker compose -f external.compose.yml up -d
```

Внешний режим не запускает локальный privileged-worker. Перед переходом с
локального режима остановить локальный Compose без `-v`; оба web-варианта
используют одно имя проекта и volume прогресса. Для нескольких workers перечислить
их приватные URL через запятую в `CHECKER_URLS`. Один URL соответствует одному
параллельному стенду. Запускать отдельные worker-проекты с разными портами.
За пределами WireGuard использовать HTTPS с доверенным сертификатом и firewall;
Bearer-токен сам по себе не шифрует соединение.

### Ресурсы И Состояние

100 игроков не означают 100 постоянно работающих сетевых стендов. Браузеры
рисуют 3D локально и предсказывают собственное движение, а сервер хранит
авторитетное состояние. Небольшие corrections применяются плавно, но сервер
отклоняет нереалистичную скорость, проход сквозь препятствия и движение вне
текущего контекста. При диагностике или сдаче
наряда worker создаёт краткоживущую сеть и удаляет её после результата.
Очередь ограничена 100 ожидающими работами; один игрок не может занять её
несколькими одновременными проверками. Место в очереди видно в игре.

Локальные лимиты: web 1 CPU / 1 GB, каждый checker 2.5 CPU / 3 GB. В текущем
Compose работают два независимых checker, поэтому одновременно выполняются две
проверки; 20 игроков могут отправить задания одновременно, из них 18 будут
ждать в очереди. Это не означает 20 одновременно работающих сетевых стендов.
На общем CUT-хосте (8 логических CPU) увеличение числа checker требует отдельной
машины или подтверждённого резерва ресурсов. [Измерения и ограничения тестов](src/tests/RESULTS.md).

Прогресс сохраняется в `network_progress` раз в 5 секунд и при штатном завершении.
Записи атомарны. Профиль и квоты привязаны к проверенному Yandex ID, а не к cookie:
повторный вход или другой браузер возвращает те же три наряда. Сессионная cookie
HttpOnly/SameSite=Lax, срок 7 дней; имена отличаются от cookie RPG. OAuth использует
одноразовый state, привязку к браузеру и PKCE. На аккаунт допускаются до 5 входов,
но только одна сессия управляет игрой одновременно. Вход ограничен до 300 запросов
в минуту с IP; игровой API до 45 запросов/с на аккаунт, с повторным учётом после
чтения тела запроса. Сетевые проверки ограничены 20/мин и одной активной/ожидающей
работой на аккаунт. Анонимные запросы больше не занимают слоты профилей.

При первом входе через Яндекс старая анонимная cookie этого браузера позволяет
однократно перенести прежний прогресс. Исходные файлы сохраняются как резервные
и не занимают квоту OAuth-профилей. Ранее выданные допуски без версии усиленной
приёмки нужно подтвердить заново: кабели и конфигурации не удаляются. Очистка
cookie не создаёт новый профиль для того же Yandex ID. OAuth не доказывает, что
разные аккаунты принадлежат разным людям. Сохранения и секретный volume нельзя
удалять при обновлении. `docker compose down -v` удаляет прогресс.

Консоль LabOS намеренно ограничена перечисленными в `help` командами. Это не
полный Linux shell и не точная копия CLI конкретного производителя. В worker
передаётся типизированная конфигурация, а не командная строка игрока. Флаг
выдаётся web-сервером только после положительных проверок актуальной ревизии
монтажа и реальной сети; изменение конфигурации во время проверки делает её
результат устаревшим. Диагностическая команда сама по себе флаг не выдаёт.

Локальный запуск и проверки выполняются из `admin/network_ops/src/`.
`npm start` читает настройки из `../deploy/.env`.

Проверки из каталога `src/`:

```sh

npm test
docker build --target checker -f ../deploy/Dockerfile -t labx-network-checker:local .
docker compose -f tests/checker-compose.yml up -d
npm run test:checker

npm run test:camera

node tests/panels-browser.mjs
```

QA-worker доступен только на `127.0.0.1:9135`, использует отдельный тестовый токен
и не работает с личными сохранениями. Браузерные проверки используют Chromium
или установленный Google Chrome на macOS; поздние сетевые состояния частично
подготавливаются авторскими фикстурами. Отдельно проверяется реальное перетаскивание
16 жил и сжатие кримпера в 3D.

### Античит И Блокировки

Сервер отклоняет недопустимые действия независимо от накопленного счёта.
Автобан по умолчанию действует 24 часа и привязан к проверенному Yandex ID,
а не к IP или cookie. Сброс наряда, повторный вход, другой браузер и перезапуск
сервера не снимают блокировку. Инвентарь и прогресс сохраняются.

Подтверждённые сигналы: попытка передать серверные поля состояния/награды
(4 балла), выдуманный токен текущего жеста инструмента (4), заведомо невозможное
перемещение после подтверждения коррекции сервера (3). Порог: 12 баллов
и минимум 3 сигнала за 5 минут. Повторы одного детекта в течение 2 секунд
не добавляют баллы. Первые сигналы показывают предупреждение.

Потерянные коррекции, запоздалые запросы, столкновения, ошибки сборки и консоли
не приводят к автобану. Старые команды сборки и превышение частоты запросов
только записываются в аудит. Проверка движения учитывает серверный бюджет,
задержку и начальный период синхронизации; не всякая отклонённая координата
считается читом. Это не детектор использования ИИ: автоматизацию допустимых
действий он не отличает от человека и полного отсутствия обходов не гарантирует.

Бан блокирует игровой API во всех сессиях аккаунта, отменяет ожидающие проверки
и запрещает выдачу результата уже выполняющихся. Экран блокировки показывает
срок и идентификатор для обращения к организатору. Уже полученный флаг нельзя
«забрать назад»; блокировка на внешней CTF-платформе остаётся отдельной процедурой.

Длительность меняется через `ANTICHEAT_BAN_SECONDS` в `.env` (60..2592000 секунд),
после чего нужно пересоздать web-контейнер. Новое значение применяется к новым
банам. На аккаунт хранятся последние 100 событий аудита без OAuth-секретов
и исходных токенов жестов. Детекты и баны сохраняются сразу; при ошибке записи
доступ остаётся заблокированным в памяти, сервер пишет сообщение в лог
и повторяет сохранение каждые 5 секунд. До успешной записи аварийная потеря
процесса может потерять последние события, поэтому ошибки диска требуют внимания.

Команды организатора из `deploy/`:

```sh
docker compose exec -T network_ops node server/anticheat-cli.mjs list
docker compose exec -T network_ops node server/anticheat-cli.mjs events YANDEX_ID
docker compose exec -T network_ops node server/anticheat-cli.mjs unban YANDEX_ID "Причина разблокировки"
```

Управление доступно только через Unix socket `/app/data/ac.sock` с правами 0600,
не через публичный HTTP-порт. Каталог данных имеет права 0700 и должен принадлежать
пользователю приложения (стандартный named volume уже подходит). Разблокировка
сбрасывает штрафные баллы, но сохраняет аудит и прогресс; при ошибке сохранения
доступ не открывается. После снятия бана игрок нажимает «Проверить доступ».

## Выдать участникам

Три ссылки на общий сервис с параметрами `level=easy`, `level=medium`, `level=hard`.
На платформе создать три задачи категории ADMIN с отдельными флагами.
Каталоги `src/server/`, `src/checker/`, `solve/`, `deploy/.env` и volumes участникам не выдавать.
HTTP-сервер публикует только клиентскую сборку и собственный API, не файлы проекта.

## Описание

Одиночный 3D-симулятор сетевого техника по открытому уровню `LEGEND.md`.
Первое лицо, подробные стойки, разъёмы, витая пара, кабельные лотки, верстак,
кримпер, CRT и шум. Названия помещений не используют номера камер канона.
Нет PvP или общих игровых объектов. Настенный служебный дробовик позволяет
отстреливать крыс; попадания не повреждают сетевое оборудование.
Клик по сцене захватывает курсор для обзора мышью; Escape освобождает его.
ЛКМ или E взаимодействует с объектом под прицелом. При переходе к верстаку,
панели, консоли и диалогам курсор автоматически освобождается для работы руками.
Инвентарь открывается и закрывается на I, задания на J; по умолчанию обе панели
скрыты. Они не прерывают движение, обзор, стрельбу и выбор инструментов.
Escape освобождает курсор, оставляя панели открытыми; клик по сцене возвращает
обзор. Закрыть панель можно той же клавишей или крестиком. Консоль и модальные
диалоги по-прежнему блокируют управление. Горячие клавиши используют физические кнопки
независимо от раскладки и не срабатывают при вводе текста в консоли.

Быстрый выбор инструментов: в комнате `1` осмотр/разъёмы, `2` забивка,
`3` сертификатор, `4` тонер, `5` консольный кабель. На верстаке `1` руки,
`2` бокорезы, `3` стриппер, `4` кримпер, `5` тестер. Поддерживается и цифровой
блок клавиатуры. Под инструментами нет плашек выделения; цифры не выполняют
саму операцию монтажа. Во время перетаскивания, ввода текста и модальных
диалогов переключение отключено. Клавиша `Q` по-прежнему переключает дробовик.

Звук запускается после первого клика или нажатия клавиши. Оригинальный тихий
электронный фон синтезируется локально через Web Audio, без внешних треков,
загрузок и сторонних сервисов. Музыка приглушается у верстака, в консоли
и диалогах, а также на время важных звуковых событий. Пауза, скрытие вкладки,
выход и бан останавливают аудио. Вверху расположены общий mute и отдельные
настройки громкости музыки и эффектов; предпочтения сохраняются в браузере.
Плавная смена громкости поддерживает Firefox без `cancelAndHoldAtTime`.
Ошибка аудиоустройства не прерывает отрисовку, переход к верстаку и ввод.

Разные звуки сопровождают выбор инструментов, резку, зачистку, обжим, контакт
жилы, соединение разъёмов, питание, измерения, ошибки и приёмку наряда.
Результаты операций озвучиваются после ответа сервера и не раскрывают скрытые
дефекты до измерения. Добавлены шаги, механика перезарядки и пустого магазина;
звуки крысы и искр учитывают расстояние и сторону относительно камеры.
Ограничение повторов и компрессор сдерживают резкие пики и наложение эффектов.

Монтаж состоит из отмеривания кабеля, снятия оболочки с выбранной глубиной,
раскладки восьми жил на каждом конце, подрезки, установки RJ45 и обжима движением
рукояток. Повреждённую жилу нельзя исправить повторной отправкой «хорошей» глубины:
надо отрезать конец, потеряв часть длины. Кабель можно вернуть на верстак, проверить,
перемаркировать, подключить к конкретным портам и провести через точки лотка.
Слишком короткий кабель не подключается. Плохая разделка даёт разрыв цепи
или split pair; обычный тестер и сертификатор показывают разные результаты.
Изоляцию отдельных жил снимать не требуется.

Ход стриппера задаёт длину снятой оболочки, а подрезка на направляющей оставляет
не более 12 мм расплетённых жил у разъёма. Приёмка учитывает конечную длину,
в том числе у ранее сохранённых подрезанных кабелей, без перезаписи прогресса.
Подрезка не восстанавливает надрезанные жилы, не исправляет распайку и не лечит
повреждения крысы. «Ручной монтаж всех линий» проверяет происхождение и завершение
сборки, «Кабельные линии» отдельно проверяет качество: один дефект больше
не отображается как две одинаковые ошибки.

Новые наряды начинают с пустым инвентарём и без подключённых патч-кордов:
Easy требует 4 кабеля по схеме, Medium 6, Hard 10. Все изготавливаются вручную.
Схема соединений есть в регламенте, скрытая линия розетка/PP-01 остаётся внутри
стены. Существующие сохранения не обнуляются: для пустого старта старого наряда
нужен его явный сброс. При зачистке сервер перемешивает восемь жил каждого конца;
порядок сохраняется при обновлении страницы и не меняется от повторной команды
зачистки. После отрезания конца и новой зачистки выполняется новая перестановка.

Каждые 5 минут активного времени текущего наряда из вентиляции появляется одна
крыса. Таймер и крыса сохраняются; любые разрешённые игровые действия, включая
API-действия без world-пакетов, поддерживают активное серверное время. Через
2.5 секунды отсутствия активности игра переходит на паузу, на которой сервер
запрещает сборку, консоль, движение и проверки до явного возобновления.
Пауза, смена наряда и выход отменяют допуск ещё выполняющейся проверки.
Крыса обходит мебель по A* (PathFinding.js),
выбирает доступный напольный кабель, грызёт его 10 секунд и после одного обрыва
убегает. Без доступной проводки она бегает по лаборатории и затем уходит.
Верхние лотки защищают проложенные через них кабели от этой угрозы.
Перегрызенная линия теряет линк, искрит и даёт электрические дуги. Повреждение
в середине кабеля не устраняется повторным обжимом: его нужно отключить,
утилизировать через верстак и заменить новым. Обрыв увеличивает ревизию,
поэтому проверка ранее исправного стенда не выдаст флаг по устаревшему снимку.

Дробовик находится на задней стене у входа. Забрать его через E или взаимодействие,
ЛКМ стреляет, R перезаряжает, Q убирает/достаёт оружие. Магазин на 6 патронов,
перезарядка 2.4 секунды, запас патронов не ограничен. Сервер проверяет наличие
оружия, патроны, темп стрельбы, направление, дальность и препятствия. Положение
игрока для выстрела ограничено комнатой и накопленным бюджетом перемещения;
это не защита от автоматического прицеливания в одиночной игре.
Искрение стилизованное, не физическая модель Ethernet/PoE.

На верстаке нет панели кнопок сборки: бухта, линейка, бокорезы, стриппер,
разъём RJ45, кримпер и измерители находятся в 3D на столе. Инструменты
перетаскиваются к заготовке, оболочка снимается протягиванием стриппера,
рукоятки кримпера сжимаются движением мыши. Шкалы показывают длину и ход
инструмента; глубина ножа меняется перетаскиванием колеса стриппера.
Бирки A/B выбирают конец, лоток «ГОТОВО» переносит патч-корд в инвентарь.
Утилизация заготовки требует подтверждения. Проложенные провода используют
скруглённую трассу без провисания геометрии ниже пола.

Инструменты имеют отдельные корпуса, металлические губки, шарниры, пружины,
винты, резиновые накладки и насечки. На приборах есть экраны, органы управления
и контакты разъёмов. Микрофактура металла и полимера формируется локальными
растровыми картами шероховатости и рельефа; материалы повторно используются
при обновлении верстака. При обжиме рукоятки поворачиваются на шарнирах,
а не растягивают корпус и текстуры. Механика жестов и серверные проверки прежние.

Консоль поддерживает `ip a`, `ip l`, `ip r`, `ip neigh`, `dhclient`,
`nslookup archive.lab`, `dig [@DNS_IP] archive.lab [TYPE] [+short]`,
`ping -c 1 archive.lab`, `traceroute`, `hostname`, `clear` и прежние команды
оборудования. `help` содержит только список команд, подробности находятся в
`ip --help`, `dig --help` и аналогичной справке остальных команд.
Адреса, линк и DHCP-адреса считываются с реального стенда; DNS-запросы
выполняются настоящими `dig`/`nslookup` внутри namespace устройства.
Разрешены только имена `.lab` и DNS-серверы выделенной сети наряда.

Easy: один VLAN, розетка/патч-панель, питание коммутатора, IPv4, шлюз и DNS.
Medium: неисправная разделка PP-01, VLAN 10/20/30, trunk, DHCP, IP forwarding
и ограничение доступа регистратора к TCP/22 архива при сохранении HTTP.
Hard: треугольник коммутаторов с RSTP, два маршрутизатора с FRR OSPF, основной
и резервный uplink, ACL, проверка обрыва основного линка и холодного старта
со startup-config.
Замкнутый L2-контур с отключённым RSTP отклоняется до запуска, чтобы не
создавать намеренный broadcast storm на worker. При включённом RSTP состояние
блокируемого порта проверяется у настоящего Open vSwitch.

Сетевые проверки используют настоящие адреса, виртуальные Ethernet-интерфейсы,
DHCP-обмен, DNS A-ответы, HTTP-запросы и TCP-соединения. TCP/22 архива является
службой проверки доступности порта с SSH-баннером, не полноценным SSH-сервером.
Ethernet-монтаж, длина, раскладка и инструментальные дефекты моделируются сервером;
это не электромагнитная симуляция помех. Клиент рисует и прогнозирует движение,
сервер проверяет бюджет перемещения и пересечение мебели, дистанцию, текущий
инструмент и рабочий контекст. Для зачистки/обжима передаются начало, точки и конец
жеста с одноразовым токеном; результат рассчитывается сервером. Токен привязан к
кабелю, концу, ревизии и контексту. Старые смысловые cut/strip/wire/crimp-команды
по HTTP отвергаются. Обязательны все физические линии схемы, ручное изготовление,
питание оборудования, а в Medium также прозвонка линии и проверка панели.

Публичное состояние содержит только данные отображения. Полные конфигурации,
startup-config, скрытая глубина повреждения и автоматические результаты тестов
в него не входят. Консольные данные доступны только у подключённого устройства,
измерения через соответствующий инструмент; раскладка жил видна на открытом
верстаке или панели. Автоматизацию корректных последовательностей ввода или
помощь ИИ исключить нельзя: эти проверки закрывают обход механик, но не доказывают
«человечность» движений. Генератор индивидуальных задач в этом изменении не добавлен.
