# Сетевая смена: прохождение

## Управление

Войти через Яндекс. Прогресс хранится за Yandex ID; если игра приостановлена,
возобновить её кнопкой «Продолжить». На паузе монтаж и консоль недоступны.

ПК: клик по сцене захватывает курсор, мышь свободно поворачивает взгляд по
горизонтали и вертикали. WASD перемещает, Shift ускоряет. Escape освобождает
курсор для панелей; следующий клик по сцене снова включает обзор.
I открывает/закрывает инвентарь, J задания. Они не освобождают курсор и не
блокируют движение, обзор или стрельбу. Escape освобождает курсор, не закрывая
панели; клик по сцене снова включает обзор. Крестик или I/J закрывает панель.
При захваченном курсоре ЛКМ или E взаимодействует с объектом под прицелом;
к оборудованию нужно подойти. Обзор с зажатой ПКМ без захвата также доступен.
Верстак открывается кликом по столешнице или кнопкой фокуса рядом с ним.
На верстаке и при открытии окон курсор автоматически освобождается.
Escape или кнопка со стрелкой возвращает обзор от первого лица.
На столе все инструменты выбираются непосредственно мышью; нижняя панель
содержит только инструменты для работы с оборудованием вне верстака.

1. Протянуть жёлтый конец бухты вдоль линейки, отмерить нужную длину.
   Перетащить красные бокорезы к отметке, чтобы отрезать заготовку.
2. Выбрать конец кабеля биркой A/B. При необходимости перетащить чёрное
   колесо жёлтого стриппера: глубина ножа должна быть не больше 1.4 мм.
3. Перетащить стриппер на оболочку, затем потянуть установленный инструмент
   вниз вдоль кабеля. Ход снятия оболочки показывается в миллиметрах;
   окончательная длина расплетённых жил задаётся последующей подрезкой.
4. Перетащить каждую из восьми жил на пронумерованные направляющие T568B:
   бело-оранжевая, оранжевая, бело-зелёная, синяя, бело-синяя, зелёная,
   бело-коричневая, коричневая. После зачистки жилы лежат в случайном порядке;
   определять их нужно по цвету, а не по исходной позиции. На коврике есть образец.
5. Перетащить бокорезы к концам разложенных жил, чтобы подровнять их по
   направляющей на 12 мм. Это убирает лишнюю длину, но не лечит глубокие надрезы.
   Перенести прозрачный разъём слева на концы жил.
6. Установить синий кримпер на разъём, затем сжать рукоятки горизонтальным
   движением мыши до зелёной отметки. Повторить со вторым концом кабеля.
7. Перетащить тестер и сертификатор на кабель. Результат виден над приборами
   и в журнале. При повреждении перенести бокорезы на оболочку, отрезать
   плохой конец и повторить монтаж. Повреждение сохраняется до переделки.
8. Нажать лоток «ГОТОВО», чтобы убрать патч-корд в инвентарь. Красная ёмкость
   справа утилизирует заготовку только после подтверждения.

Законченный кабель выбрать в списке, подключить последовательно
к двум портам. Клик по жёлтым точкам лотка между подключениями добавляет трассу;
на её длину должен хватать отрезанный кабель. У отключённого кабеля есть кнопка
возврата на верстак. Для маркировки использовать значок бирки.
Каждый конец отключается отдельно, рядом с соответствующим портом. Маркировка
подключённого кабеля также требует подхода к нему с маркером.

Консоль: выбрать инструмент с терминалом, подойти к устройству и нажать его
голубой порт CONSOLE. Затем вводить команды в консоли. `help` показывает только
названия команд; `<command> --help` содержит синтаксис и описание.
`ip a`, `ip l`, `ip r`, `ip neigh` считывают сетевое состояние с Linux-стенда,
`nslookup archive.lab` и `dig archive.lab +short` выполняют реальные DNS-запросы;
стрелки вверх/вниз переключают историю. Зелёная кнопка на стойке переключает
питание. Перезапуск загружает сохранённую конфигурацию; `write memory` сохраняет.
Удалённое открытие консоли не допускается. Закрытие окна или Escape отключает
текущий консольный контекст; для повторного открытия взаимодействовать с портом.

Во всех примерах заменить `42` на второй октет из адресного плана своего наряда.
Наряды независимы. Отдельная кнопка сбрасывает только текущий наряд.

Все патч-корды нужно изготовить вручную, включая линии к архиву и маршрутизаторам.
Полная схема портов находится в регламенте. Приблизительно раз в 5 минут активной
игры появляется крыса. Её можно остановить дробовиком с задней стены: E забирает,
Q достаёт/убирает, ЛКМ стреляет, R перезаряжает. Крыса грызёт напольную линию
10 секунд; кабели на верхних лотках защищены. Повреждённый кабель отключить,
вернуть на верстак, утилизировать и изготовить замену. Повторный обжим не поможет.

## Easy

Изготовить исправный прямой кабель, соединить `pc:eth0` с `outlet:j1`.
Изготовить ещё три кабеля: `panel:j1` с `swa:p1`, `swa:p4` с `r1:lan`,
`r1:srv` с `archive:eth0`. Включить SW-A.
На локальной консоли рабочей станции:

```text
ip addr add 10.42.10.20/24 dev eth0
ip route add default via 10.42.10.1
dns server 10.42.99.10
write memory
ping archive.lab
```

Сдать наряд. Принятие требует физического монтажа, адресации, правильного DNS
ответа и настоящего HTTP-доступа к архиву с рабочей станции.

## Medium

Изготовить и подключить шесть кабелей по схеме из регламента, включая
`pc:eth0` → `outlet:j1`, `panel:j1` → `swb:p1`, `swa:p4` → `r1:uplink`,
`cam:eth0` → `swb:p2`, `archive:eth0` → `swa:p3`, `swa:p2` → `swb:p4`.

Тональным генератором проследить `outlet:j1` до `panel:j1`. На PP-01 ошибочная
раскладка пар: простая прозвонка не выявляет дефект структуры. Подойти к панели
с инструментом забивки, открыть разделку и разложить T568B. Выполнить проверку
сертификатором. Между `swa:p2` и `swb:p4` должен быть исправный прямой кабель.

SW-B:

```text
switchport access 10 dev p1
switchport access 20 dev p2
switchport trunk 10,20,30 dev p4
write memory
```

SW-A:

```text
switchport trunk 10,20,30 dev p2
switchport access 30 dev p3
write memory
```

Порт p4 SW-A уже trunk к R-1. На R-1:

```text
ip forward on
acl deny cameras ssh
write memory
```

DHCP-сервер уже настроен на R-1, оба клиента ждут аренду. Провести проверки:
станция должна получить VLAN 10, регистратор VLAN 20; HTTP должен работать
у обоих. Станции разрешён TCP/22 архива, регистратору запрещён. Отключение
всей сети или запрет всего трафика не считаются исправлением ACL.

## Hard

Изготовить все десять кабелей по схеме в регламенте, включая треугольник
SW-A/SW-B/SW-C и оба линка `r1:wan1` → `r2:wan1`, `r1:wan2` → `r2:wan2`.
Через `show links` и осмотр проверить получившуюся топологию.
На всех трёх коммутаторах включить RSTP и сохранить конфигурацию:

```text
bridge rstp on
write memory
```

На SW-A задать `bridge priority 4096` и снова сохранить. На SW-C вернуть VLAN 20
в trunk: `switchport trunk 10,20 dev p4`, затем `write memory`. На R-1:

```text
router ospf on
acl deny cameras ssh
write memory
```

На R-2:

```text
ip forward on
router ospf on
write memory
```

Адреса интерфейсов подготовлены, но RSTP, OSPF и forwarding на R-2 исходно
отключены; в trunk SW-C потерян VLAN регистратора. Основной uplink использует
`10.42.250.0/30`, резервный `10.42.251.0/30`.
Архив за R-2 расположен в `10.42.99.0/24`; маршрут должен быть изучен по OSPF.
Проверка отключает `wan1`, требует работоспособного маршрута через `wan2`,
а затем уничтожает временный стенд и создаёт его заново из startup-config.
Без сохранения настроек второй этап не проходит.

Файлы в этой папке предназначены автору. `fixtures.mjs` делает те же изменения
через игровые действия и команды, а не выставляет `won` напрямую. Реальные
сетевые условия отдельно проверяются worker-тестом.
