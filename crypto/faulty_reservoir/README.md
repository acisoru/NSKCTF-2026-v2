# Неисправный источник | Medium | crypto

## Информация

> Из карантинного архива Лаборатории X извлекли 28 подписанных строк журнала ALICE. На станции уверяли, что источнику случайных чисел «хватает» 232 бит. Закрытая запись зашифрована ключом, связанным с секретным ключом подписи. Восстановите запись.

## Деплой

Деплой отсутствует. Публичный файл выдаётся участникам через CTFd.

## Выдать участникам

[public/telemetry.json](public/telemetry.json). Каталоги `src/` и `solve/` не выдавать.

## Описание

В файле находятся 28 корректных подписей ECDSA на кривой secp256k1 и исходные строки журнала. Каждый одноразовый скаляр выбирался из диапазона `1..2²³²−1` вместо полного 256-битного диапазона. Подписи не раскрывают скаляры напрямую. Закрытая запись зашифрована AES-256-GCM; ключ выводится из секретного скаляра подписи. По уровню турнира эта задача рассчитана на Hard+.

## Решение

Для подписи `(rᵢ, sᵢ)` и SHA-256-хеша сообщения `zᵢ` выполняется `sᵢkᵢ = zᵢ + rᵢd (mod n)`. Значит, `kᵢ = aᵢd + bᵢ (mod n)`, где `aᵢ = rᵢ/sᵢ`, `bᵢ = zᵢ/sᵢ`, а `n` — порядок группы. Каждый `kᵢ` лежит в интервале `[1, 2²³²)`: старшие 24 бита известны. Из 28 сравнений строится решётка для задачи о скрытом числе. Масштабируем координаты одноразовых скаляров на `2²⁴`, сокращаем базис алгоритмом LLL и находим ближайший вектор к серединам интервалов. Его последняя координата даёт `d`.

Полученный `d` проверяется по открытому ключу. Затем вычисляется `SHA256(domain || d.to_bytes(32, 'big'))` и расшифровывается запись AES-GCM. Проверка тега подтверждает результат. В открытом тексте находятся флаг и улика о расходе склада в годы пробела.

[Скрипт решения](solve/solve.py): установить `fpylll cysignals ecdsa pycryptodome`, затем выполнить `python3 solve/solve.py`.
