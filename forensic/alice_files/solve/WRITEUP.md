# Авторское решение

Единственный выдаваемый файл - `public/scan_03.pdf`, 11 страниц.
Страницы 1-8 содержат скан утёкшего доклада. Приложение на страницах 9-11
содержит 138 событий для 24 сотрудников. В колонке «Зона номер» записаны серийники
устройств; 00000000 - вход в здание. Происхождение экземпляра и условия работы приведены
в описании задания; других файлов не требуется.

## 1. Извлечь растровые страницы

На каждой из первых восьми страниц PDF находится одно исходное изображение.

```python
from pypdf import PdfReader

reader = PdfReader("scan_03.pdf")
image = reader.pages[0].images[0].image.convert("RGB")
```

Можно использовать `pdfimages -j`. Закрашенные фрагменты не восстанавливаются:
изображение уже содержит заменённые пиксели, а скрытого текстового слоя нет.
Для решения цензура не нужна. Приложение содержит обычный видимый текст,
из которого удобно копировать журнал.

## 2. Проявить жёлтый тонер

Жёлтый пигмент поглощает синий свет. В канале B точки темнее бумаги;
увеличение контраста делает их заметнее. Чтобы подавить серые буквы и
неравномерную подсветку, удобно вычислить `min(R, G) - B` и вычесть
размытую версию этого сигнала. Локальные максимумы дают центры точек.
Цветовые артефакты JPEG пока сохраняются, поэтому нужна следующая проверка.

## 3. Найти решётку и повторения

Расстояния между близкими точками имеют пик около 12 пикселей. Направления
соседних пар дают малый угол поворота; затем решётка уточняется по множеству
точек. Артефакты, не попадающие в целочисленные узлы, отбрасываются.

Корреляция обнаруживает период 32 шага по обеим осям. В таком квадрате
находятся два одинаковых блока 15×8 со сдвигом. Усреднение по повторениям
помогает восстановить пропуски тонера, закрытые текстом точки и повреждения
JPEG. Примерно 6,5% точек пропущены при генерации, поэтому одного блока
может оказаться недостаточно для корректного чтения.

## 4. Проверить чётность и декодировать

Основа - [EFF DocuColor Tracking Dot Decoding Guide](https://w2.eff.org/Privacy/printers/docucolor/).
Столбцы нумеруются слева направо от 1 до 15; после верхней строки чётности
семь строк данных имеют веса `64, 32, 16, 8, 4, 2, 1` сверху вниз.

| Столбцы | Значение |
|---|---|
| 1 | Нечётная чётность строк данных |
| 2 | Минута |
| 3, 4 | Не используются |
| 5 | Час |
| 6 | День |
| 7 | Месяц |
| 8 | Год без столетия |
| 9 | Не используется |
| 10 | Разделитель, 127 |
| 14, 13, 12, 11 | Серийник: две цифры BCD на столбец |
| 15 | Конфигурация, в этом профиле 0 |

Все 15 столбцов и семь строк данных должны иметь нечётное число точек.
Верхняя строка в целом чётная: проверять нечётность всех восьми строк ошибочно.
Неверное начало или ориентация блока отбрасываются по чётности, разделителю
и допустимости дат. Дата и время двоичные; серийник читается в BCD.

Все восемь страниц дают серийный номер **00483729** и время
**16.09.2026 20:06** по часам принтера. Пары серийника: `00 48 37 29`.

## 5. Сопоставить с журналом

Полученный серийник совпадает со значением 00483729 в колонке «Зона номер».
По условию часы оборудования используют UTC. По местному времени Новосибирска
это **17.09.2026 03:06**, то есть следующий календарный день.

Лебедева, пропуск B031, вошла в зону 00483729 в 03:03:27 и вышла в 03:09:40.
Она единственная присутствует там в течение всей минуты
`[03:06:00, 03:07:00)`. Её вход в здание - 01:05:30, выход - 03:25:11.
Волкова в это время находится в зоне 00635127, Громов - в 00542817,
Тихонова - в 00712643. Совпадения по времени недостаточно: нужен номер зоны.

Минута печати не совпадает ни с одной явной отметкой журнала: её нужно
восстановить из MIC, а затем проверить присутствие сотрудника внутри интервала.

Ответ: `nskctf{lebedeva_0306}`.
