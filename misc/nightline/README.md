## Деплой

Из корня репозитория, только для NIGHTLINE:

```sh
cd misc/nightline/deploy
docker compose up --build -d --wait
```

Готовый `deploy/.env` включён в репозиторий: флаг, секрет сессий, пароль
PostgreSQL и параметры сервера уже заданы. Генерировать или копировать
настройки не нужно. Перед игрой проверить `FLAG` и выставить то же
значение на платформе. `.env` предназначен только для организаторов;
в образ приложения он не копируется и через HTTP не раздаётся.

Два сервиса: `nightline_app` (Python 3.13, FastAPI, Pillow) и
`nightline_db` (PostgreSQL 17). Снаружи доступен только HTTP-порт `3386`;
порт БД не публикуется. На хосте не нужны Python-зависимости приложения.
Для сборки и запуска достаточно одного каталога `deploy/`: в `deploy/src/`
лежит полная копия авторских исходников из `src/`, а build-контекст — `.`.
Зависимостей от соседних каталогов и внешних bind-mount нет.
Сервер работает от UID 10001,
с read-only файловой системой; у обоих сервисов есть healthcheck,
лимиты ресурсов и политика перезапуска.

Данные сохраняются в именованном томе `nightline_pgdata`. Смена контейнеров
не сбрасывает сессии и решения. `docker compose down` оставляет том;
`docker compose down -v` удаляет прогресс без возможности восстановления.
Старые локальные данные прототипа в задачу не включены.

По умолчанию слушает `0.0.0.0:3386`. Для локального запуска:
`BIND_ADDRESS=127.0.0.1 docker compose up --build -d --wait`.
Другие настройки — в `deploy/.env`. За HTTPS выставить
`COOKIE_SECURE=true`; доверять forwarding-заголовкам только от своего
reverse proxy через `FORWARDED_ALLOW_IPS`. `/healthz` проверяет соединение
с PostgreSQL. Логи: `docker compose logs --tail=100 nightline_app`.

После изменения авторских исходников обновить копию для деплоя из корня
репозитория:

```sh
python3 misc/nightline/solve/sync_deploy.py
python3 misc/nightline/solve/sync_deploy.py --check
```

Готовая копия уже включена в Git; при обычном развёртывании эти команды
не нужны. [Скрипт синхронизации](solve/sync_deploy.py) проверяет побайтовое
совпадение всех runtime-файлов, включая карту, frontend, шрифт и зависимости.

Авторские проверки только этой задачи, из `deploy/` полной копии репозитория
(каталог `solve/` для запуска сервиса не требуется):

```sh
docker compose exec -T nightline_app python - < ../solve/check_service.py
docker compose exec -T nightline_app python - audit --count 25 < ../solve/manage.py
```

Проверка API создаёт собственные временные сессии в работающей базе,
проверяет их и удаляет. Команды не запускают другие задания. Вторая
команда проверяет генератор без обращения к пользовательским сессиям.
Браузерный плейтест и нагрузочная проверка турнирного масштаба — отдельно;
эти команды их не заменяют.

## Описание

Алгоритмическая misc-задача на синхронизацию конечного автомата.
В условном городе 20 пронумерованных узлов; из каждого выходит ровно одна
направленная красная и одна синяя дорога. Склад — один из тех же узлов.
Начальная точка может быть любой, включая склад. Одна строка из `R` и `B`
должна привести на склад из всех начальных точек после последней команды.
Промежуточное попадание на склад не останавливает курьера. Допускается
любое корректное решение длиной от 1 до 128, не обязательно кратчайшее.

Город индивидуален для сессии. Таблица переходов, seed и эталонный ответ
остаются на сервере; через HTTP выдаются только растровые слои PNG.
Красная дорога сплошная, синяя пунктирная; есть стрелки и буквы команд.
Пересечение линий вне узла не создаёт соединения. Узлы — элементы схемы
тренажёра, не номера камер и не помещения лаборатории.

Красные переходы образуют цикл по всем узлам, синие дают слияния состояний.
Генератор проверяет разрешимость BFS по подмножествам и принимает города
с кратчайшим ответом от 22 до 72 команд. Ошибочная попытка сообщает только
неуспех, без размера остаточного множества. Сессия живёт 48 часов;
черновик, заметки и пометки сохраняются в браузере.

PostgreSQL хранит хеши сессионных токенов, закрытые seed, попытки и лимиты.
Запросы параметризованы; конкурентные изменения сессии сериализуются
через `SELECT ... FOR UPDATE`. Повтор UUID возвращает сохранённый ответ,
не увеличивая счётчик. Cookie HttpOnly/SameSite=Strict, изменяющие запросы
защищены CSRF; есть ограничения размера тела и частоты запросов.
Версия генератора при переносе не менялась: для существующей базы нельзя
менять алгоритм без миграции или сохранения снимков автоматов.

Растровая стадия не даёт таблицу простым чтением JSON или DOM, но не
гарантирует защиту от ИИ: агент с обработкой изображений тоже может
восстановить граф. Приоритет — однозначная карта и честная решаемость.

## Решение

1. Скачать карту своей сессии, при необходимости отдельно слои `R` и `B`.
2. По стрелкам восстановить два перехода для каждого из 20 узлов.
3. Начать с множества всех узлов и искать не путь отдельного курьера,
   а последовательность образов этого множества.
4. Выполнить BFS по битовым маскам: `R` и `B` переводят множество
   возможных позиций через соответствующие таблицы.
5. Достигнув одноэлементного множества склада, восстановить слово
   по родительским ссылкам и отправить его в ту же сессию.

[Подробный разбор и формат таблицы](solve/WRITEUP.md).
[Независимый решатель](solve/solve.py) использует только стандартную
библиотеку Python и вручную восстановленную таблицу.
[Инструменты организатора](solve/manage.py) умеют получать эталон по
закрытому seed или идентификатору города из PostgreSQL; через HTTP
они недоступны и в образ приложения не включены.
