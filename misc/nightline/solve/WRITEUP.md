# NIGHTLINE: авторский разбор

## Визуальная стадия

Каждый номер на карте — состояние. Стрелка задаёт направление перехода,
цвет и буква — команду. Красная дорога сплошная, синяя пунктирная.
Петлю нужно записать как переход из узла в него же. Пересечение линий
между кругами игнорируется. Склад участвует в таблице на общих основаниях.

В интерфейсе можно включить только один цвет и скачать соответствующий
PNG. Для каждого номера `01..20` записываем назначения красной и синей
дорог. Получится JSON с полями `red`, `blue`, `target`:

- `red[i - 1]` — номер узла после `R` из узла `i`;
- `blue[i - 1]` — номер узла после `B` из узла `i`;
- `target` — номер зелёного склада;
- номера в файле такие же, как на карте, от 1 до 20.

У каждого участника свой город. Единой таблицы и единого маршрута нет.
Файл таблицы удобно сохранить вне репозитория, например
`/tmp/nightline-table.json`. В нём должны быть настоящие массивы из 20
чисел, а не координаты пикселей или список встреченных стрелок.

Красные переходы образуют цикл по всем 20 узлам. Это полезная проверка
переписанной таблицы. Синий цвет не обязан быть перестановкой: именно
переходы нескольких узлов в один позволяют забыть начальную позицию.

## Почему обычный поиск пути не подходит

Участник не знает, в каком узле находится курьер. Успешный путь из одного
номера ничего не говорит о других стартах. Нельзя также последовательно
«забирать» курьеров со склада: они продолжают выполнять все команды.

Пусть `S` — множество возможных текущих положений. Начинаем с
`S = {1, ..., 20}`. Для команды `c` вычисляем
`next(S, c) = {transition[c][q] : q in S}`. Число элементов не растёт,
но множество может перемещаться, не уменьшаясь. Поэтому жадный выбор
команды, которая немедленно сильнее сжимает множество, не гарантирует
успех. Нужно сохранять уже посещённые множества и искать по ним.

Цель — именно `{target}`, не произвольный одиночный узел. Можно сначала
синхронизировать в другом месте и затем довести всех по красному циклу,
но прямой BFS сразу учитывает нужный склад.

## BFS по подмножествам

Множество кодируется битовой маской из 20 бит. На маску приходится два
ребра. Всего не более `2^20` масок; нулевое множество недостижимо.
Массивы родителей и последней команды позволяют восстановить ответ.
BFS находит кратчайший ответ, хотя сервису достаточно любого до 128
команд. Решатель предварительно строит образы всех масок для двух
переходов: поиск требует `O(2^n)` памяти и `O(2^n)` операций после
такого же по порядку препроцессинга.

```sh
python3 misc/nightline/solve/solve.py /tmp/nightline-table.json
```

Вставить выведенное слово в редактор своей карты и отправить. Пробелы,
табуляции, переносы строк и нижний регистр допустимы; сервер нормализует
строку. Ошибка не сообщает, сколько позиций осталось: по ней нельзя
восстанавливать переходы через оракул промежуточного состояния.

Для отправки из скрипта задать cookie своей сессии в переменной
`NIGHTLINE_SESSION` и добавить `--url http://127.0.0.1:3386`.
Cookie не передавать в командной строке и не публиковать. Скрипт получает
CSRF-токен и отправляет маршрут в эту сессию; без cookie он только решает
введённую таблицу.

## Инструменты организатора

Из корня репозитория, с уже запущенным Docker-развёртыванием:

```sh
docker compose -f misc/nightline/deploy/docker-compose.yml exec -T nightline_app \
  python - solve --seed nightline-preview < misc/nightline/solve/manage.py

docker compose -f misc/nightline/deploy/docker-compose.yml exec -T nightline_app \
  python - preview --seed nightline-preview --output - \
  < misc/nightline/solve/manage.py > /tmp/nightline-preview.png
```

PNG во второй команде сохраняется на хосте через stdout. Это также
работает, если Docker не умеет копировать файлы из контейнерного tmpfs.

Вместо `--seed` можно передать `--puzzle-id` своего города. Этот режим
читает seed из PostgreSQL в read-only транзакции. `--json` у команды
`solve` выдаёт закрытую таблицу с нумерацией от нуля; независимый решатель
принимает её с флагом `--zero-based`. Это служебный путь проверки, не
предполагаемый способ решения участника.

`manage.py audit --count 25` проверяет серию независимых городов:
эталон принимается, одноцветные маршруты не работают, печатаются длины
кратчайших слов и время генерации. `check_service.py` дополнительно
проверяет реальный HTTP API, PostgreSQL, изоляцию сессий, конкурентные
попытки, CSRF, ограничения и выдачу флага. Он не использует браузер.

## Связь с каноном

NIGHTLINE — архивный тренажёр, а не наблюдательная система ALICE.
Комиссия управляет восстановленным контуром сама; ALICE не вмешивается
в движение. Метка HACKED находится в карантинном архиве. Потеря координат
не означает внешнего проникновения через периметр. Номера узлов не
обозначают камеры, сотрудников или допуски. Закрытые события и личности
легенды не раскрываются. Сюжетную улику платформа может добавить отдельно
по согласованию с авторами общего сюжета.
