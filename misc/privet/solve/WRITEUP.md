# Привет: как решить задачу

Нужно найти 24 числа, которые принимает программа на картинке.
Эти числа позволят открыть `quarantine.bin` и получить флаг.

Главная идея: узнать, какие числа программа ожидает в конце, и восстановить
ввод, отменяя её действия в обратном порядке.

Этот разбор и файлы из `solve/` предназначены для организаторов.

## 1. Что нам дали

В выдаче четыре файла:

- `privet.png` - картинка с программой.
- `quarantine.bin` - зашифрованное вложение с флагом.
- `unpack.py` - готовый скрипт для открытия вложения, когда числа найдены.

Из `unpack.py` видно, что эти 24 числа превращаются в байты, затем из них
вычисляется ключ шифрования. Значит, нам нужен правильный ввод для картинки.
Если просто заставить программу напечатать «успех», ключ от этого не появится.

## 2. Как читать картинку

Это язык **Piet**.

В Piet команды задаются переходами между цветами. Например, один переход
добавляет число в стек, другой складывает два числа, третий выводит символ.
Стек можно представить как список, в котором команды обычно работают
с последними элементами.

Несколько правил, которые важны именно здесь:

- Одна ячейка программы равна одному пикселю.
- Команда `push` кладёт в стек количество пикселей в цветном блоке.
- У блоков есть выступы, поэтому нужно считать всю площадь.
- Переход через белый участок не выполняет команду.
- Указатели DP и CC определяют, в какую сторону идти и откуда выходить из блока.

Подробные правила есть в [описании Piet](https://www.dangermouse.net/esoteric/piet.html).
В авторском решении их исполняет [piet.py](piet.py).

Запускаем картинку с 24 нулями и записываем выполненные команды.
Такой список команд называют трассой. Программа отвечает:

```text
privet
0
```

Нули не подошли, но мы увидели, что программа с ними делает.
В этой картинке маршрут исполнения одинаков для любого ввода. Поэтому
нулевой запуск позволяет собрать все команды проверки. Результаты вычислений
будут другими: их ещё нужно разобрать.

## 3. Делаем команды понятнее

Получилось больше 53 тысяч команд. Среди них много повторений, которые
можно заменить короткими понятными действиями.

Например, эта последовательность просто получает число 257:

```text
положить 16
положить 16
перемножить
положить 1
сложить
```

Заменяем её на «положить 257». Повороты маршрута по картинке тоже отделяем
от вычислений над вводом.

Другой частый участок двигает элементы стека командой `roll`, копирует один
из них и возвращает остальные на место. Его смысл удобно проверить на
маленьком примере. Если копируется третий элемент от конца, получается:

```text
[10, 20, 30] -> [10, 20, 30, 10]
```

Вместо всей последовательности записываем «скопировать третий элемент».
Таким же образом распознаём обычные циклические сдвиги списка.
В решателе этим занимается функция `normalize`.

После упрощения становится видна структура программы: она читает 24 числа,
проверяет диапазон, много раз изменяет и переставляет числа, а в конце
сравнивает результат с заранее записанными значениями.

Это самая трудоёмкая часть решения. Распознать Piet недостаточно: нужно
разобраться в повторяющихся участках программы. Авторский скрипт уже знает
эти шаблоны, а участнику предстоит их найти.

## 4. Почему стоит начать с конца

Смотрим, при каком условии программа печатает `1`.
Для каждого из 24 итоговых чисел она делает следующее:

```text
разница = полученное число - ожидаемое число
ошибка = разница * разница
```

Потом складывает все ошибки. Квадрат не бывает отрицательным, поэтому
сумма равна нулю только тогда, когда совпали все 24 числа.
Отдельно учитываются ошибки диапазона исходного ввода.

Ожидаемые числа записаны в самой программе. Мы можем извлечь их из команд.
Проверка снимает числа с конца стека, поэтому найденный список нужно развернуть.

Теперь мы знаем, **каким должен стать список после всех вычислений**.
Возникает идея: получится ли восстановить предыдущий список, затем ещё
предыдущий, и так дойти до ввода?

## 5. Отменяем изменение одного числа

Основной участок программы меняет одно число `x`, используя два других
числа `y` и `z` из списка:

```python
new_x = (a * x + b * y * z + c * y + d) % 257
```

Знак `% 257` означает «взять остаток от деления на 257».
Числа `a`, `b`, `c`, `d` и позиции `y`, `z` берём из команд программы.

Важная деталь: `y` и `z` этот участок не меняет. Поэтому, если известен
результат, мы можем посчитать добавку `b*y*z + c*y + d` и вычесть её.
После этого остаётся отменить умножение на `a`.

При вычислении остатков обычное деление не подходит. Вместо него умножают
на специальное обратное число. В Python его находит `pow(a, -1, 257)`.
Здесь оно всегда существует: 257 простое, а `a` находится между 1 и 256.

Обратное действие выглядит так:

```python
old_x = ((new_x - b * y * z - c * y - d) * pow(a, -1, 257)) % 257
```

Для понимания возьмём маленький пример:

```text
Было x = 10.
Программа посчитала (3 * 10 + 7) % 257 = 37.

Убираем добавку: 37 - 7 = 30.
Обратное число для 3 равно 86, потому что (3 * 86) % 257 = 1.
Восстанавливаем x: (30 * 86) % 257 = 10.
```

После каждого такого изменения программа ещё сдвигает список на известное
число позиций. При движении назад сначала отменяем этот сдвиг, а потом
восстанавливаем `x`. Это возвращает `y` и `z` на нужные места.

## 6. Отменяем сдвиг, который зависит от самих чисел

Иногда программа складывает все 24 числа и сдвигает список вправо:

```python
shift = sum(values) % 24
```

Сначала кажется, что для отмены нужно знать предыдущий список.
Но **перестановка чисел не меняет их сумму**.

Например, у списков `[10, 20, 30]` и `[30, 10, 20]` сумма одинаковая: 60.
Это верно и для наших 24 чисел. Поэтому считаем сумму уже сдвинутого списка,
получаем тот же `shift` и сдвигаем его влево на столько же позиций.

В этом участке также меняется CC, один из указателей Piet. Это влияет
на обход картинки, но отдельного изменения чисел из-за CC нет.

## 7. Восстанавливаем ввод и открываем вложение

Оба вида действий можно отменить. Берём ожидаемые числа из финальной проверки
и идём по программе назад: отменяем последний шаг, затем предпоследний
и так далее. Всего нужно отменить 480 изменений чисел и 40 дополнительных
сдвигов. В решателе это делает функция `invert`.

Получаем исходные 24 числа:

```text
123 81 29 204 121 169 83 128 21 85 136 225
170 243 172 155 226 147 12 193 251 229 115 205
```

Подаём их на вход исходной картинке. Теперь ответ такой:

```text
privet
1
```

С этим же вводом открываем вложение через `unpack.py`. Он вычисляет ключ,
расшифровывает данные и проверяет, что ключ подошёл и файл не повреждён.

Готовый [solve.py](solve.py) выполняет весь разбор автоматически.
Из корня репозитория, после установки зависимостей по README:

```sh
/tmp/privet-venv/bin/python misc/privet/solve/solve.py \
  misc/privet/public --key-out /tmp/privet-key.txt
```

Он выводит флаг с уликой и записывает найденные числа в `/tmp/privet-key.txt`.
Чтобы проверить отдельно простой скрипт из выдачи:

```sh
/tmp/privet-venv/bin/python misc/privet/public/unpack.py \
  misc/privet/public/quarantine.bin /tmp/privet-key.txt
```

Флаг:

```text
nskctf{c0l0ur_is_a_pr0t0c0l_093a1913bc5f0f6e}
```

Улика:

> Метка HACKED содержит маршрут в наблюдательную, вне покрытия камер,
> и номер допуска 000. В таблице этот допуск помечен «резервный, не выдан».

## Проверка независимым интерпретатором

Этот раздел нужен организатору для проверки сборки.
Чтобы убедиться, что картинка работает и вне нашего `piet.py`, используем
сторонний интерпретатор `npiet v1.3a`. Тесты сами переводят PNG в формат PPM,
который умеет читать минимальная сборка `npiet`.

```sh
curl -fsSL https://raw.githubusercontent.com/gleitz/npiet/843a5863a587e54155d3871f3d6ba735484e62f7/npiet.c \
  -o /tmp/privet-npiet.c
cc -O2 /tmp/privet-npiet.c -o /tmp/privet-npiet
NPIET=/tmp/privet-npiet /tmp/privet-venv/bin/python -m unittest discover \
  -s misc/privet/solve -p 'test_*.py' -v
```

Проверяются правильный и неправильный ввод, расшифровка вложения,
повреждённые файлы и повторная сборка. Решатель также запускается в отдельной
папке, где нет исходников генератора и заранее записанного ключа.
