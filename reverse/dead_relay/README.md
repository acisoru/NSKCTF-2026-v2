# Мёртвое реле | Medium | reverse

## Информация

> ALICE передала наружу образ старой служебной установки Лаборатории X. В нём восемь участков, и на каждом контролёр и исполнитель понимают одни и те же данные по-разному. Пройдите маршрут, изучите архивные записи и прошивку PULSE ROM. Возможно, установка помнит работу в те 559 суток, которых нет в журнале.
>
> Сервер: `<ip>:34320` (TCP). Нативный клиент Linux выдаётся участникам.


## Деплой

```sh
cd deploy
docker compose up --build -d
```

C++-сервер собирается в Docker, читает флаг из `deploy/flag.txt` и слушает TCP-порт 34320. Сеансы хранятся в памяти и сбрасываются при перезапуске контейнера. Публичный Linux-клиент собирается из C++ со статически связанной raylib 6.0. Скрипт `src/build_client.sh` запускает сборщик на базе Debian 12, после `strip` добавляет в исполняемый файл ROM-карту и графические ресурсы через `src/pack_assets.py`. Повторный запуск `strip` для готового файла удалит встроенный архив; при изменениях нужно пересобрать клиент.

На программном рендерере OpenGL автоматически включается облегчённая графика. `F3` переключает её и полный режим с тенями, повышенным разрешением и обработкой изображения. Сетевой протокол и путь решения в обоих режимах одинаковы.
Для сборки сервера достаточно скопировать только `deploy/`; её копии `src/server/` и `src/shared/` обновляются командой `python3 scripts/sync_task_deploy.py` из корня репозитория.

## Выдать участникам

Только [public/dead_relay](public/dead_relay) и адрес сервера. [PLAYER.txt](public/PLAYER.txt) — необязательная памятка. В исполняемый файл встроены raylib, 64-байтная ROM-карта, модели, текстуры, шрифты, шейдеры и сведения об источниках графики. При запуске клиент проверяет архив, временно распаковывает ресурсы и удаляет каталог при обычном завершении. Команда запуска: `RELAY_HOST=<ip> ./dead_relay` на Linux x86-64 с OpenGL и X11.

## Описание

Это задача уровня **Hard+++** в слоте Medium категории reverse. Игроки видят общий список продвижения и присутствие других участников на одном участке. Персонаж с архивными подсказками — запись ALICE, а не ещё один сотрудник лаборатории.

В 3D-клиенте восемь участков установки: пост допуска, склад, переправа, дренажный канал, плавильный узел, холодный архив, планировщик и ядро. В сценах есть анимированные краны и конвейер, вода, искры, стойки архива, вращающиеся кольца, операторы и дроны. На каждом участке стоят пульт и два шкафа с записями аудита. Участник ходит в режиме от третьего лица, читает записи клавишей `E`, открывает терминал клавишей `T`, вращает камеру правой кнопкой мыши и смотрит контрольный вектор прошивки по `F2`.

Сервер проверяет восемь этапов по порядку и выдаёт флаг только в конце. Пять этапов используют разные ошибки реализации, ещё три требуют восстановления преобразований прошивки, зависящих от зерна сеанса. Публичный бинарь не содержит флаг.

## Решение

Клиент общается с сервером построчным TCP-протоколом. `HELLO <имя>` возвращает токен сеанса, номер участка, баланс и 32-битное зерно. В бинаре находятся строки команд, алгоритмы преобразования и интерпретатор ROM. Для перехода используется `ACT <команда> <аргумент>`:

| Участок | Уязвимость или проверка | Действие |
|---|---|---|
| Пост допуска | Сканер приводит количество к `uint8_t`, журнал проверяет полное число. | `manifest 256`: сканер видит ноль, журнал — число больше двенадцати. |
| Склад | Проверка остатка приводит число к `uint16_t`, выплата использует всю накладную. | `salvage 65536`: склад видит ноль, начисляется 65 536 кредитов. |
| Переправа | Ключ вычисляется вращением, сложением и XOR младших 16 бит зерна сеанса. | Вычислить `rol16(((seed & 0xffff) ^ 0x9d7b) + 0x2143, 5) ^ 0x6a31`, отправить `ferry <ключ>` в десятичном виде. Плата — 5000 кредитов. |
| Дренаж | Верхняя граница проверяется, нижняя — нет. `-1` при сужении указывает на служебную плитку 255. | `seam -1 7`. |
| Плавильный узел | Контролёр берёт первый `charge`, печь — последнее одноимённое поле. | `forge charge=1,charge=9,coil=6`: контроль видит безопасный заряд 1, печь — суммарную энергию 15. |
| Холодный архив | Указатель из восьми знаков строится из зерна сеанса через LCG и алфавит из 32 символов. | Восстановить `archive(seed)` по клиенту и отправить `archive <знаки>`. |
| Планировщик | 32-битный счётчик начинается с такта 73 и переполняется в служебное окно до такта 100. | `clock 4294967295`: результат — такт 72. |
| Ядро | В 64 байтах ROM закодированы восемь операций; старшие три бита задают команду, младшие пять — аргумент. | Реализовать интерпретатор из клиента, извлечь встроенную `pulse.rom`, вычислить код и отправить `core <16 шестнадцатеричных цифр>`. |

[Полный скрипт решения](solve/solve.py) использует только стандартную библиотеку Python: `python3 solve/solve.py <ip> 34320`. Он извлекает ROM из исполняемого файла, начинает новый сеанс, проходит все участки и выводит флаг с уликой.

## Авторские замечания

Ошибки ограничены состоянием задания. Для продвижения сервер не доверяет нарисованному участку, позиции персонажа или локальной диагностике; сообщения `POS` и `PEERS` нужны только для присутствия других игроков. Графика использует [ресурсы Poly Haven под CC0](https://polyhaven.com/license); источники перечислены в [ART-CREDITS.txt](src/client/assets/ART-CREDITS.txt) внутри бинаря.
