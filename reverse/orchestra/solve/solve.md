# Solve Orchestra

## Вход и финальная проверка

`lead-part-tester` принимает три пути: скрипка, бас, фортепиано.
Через строки ошибок `fixed score or rhythm changed` и `return mismatch`
находим в декомпиляторе проверку входа и финальное сравнение. Оно выполняется
после завершения всех голосов и сравнивает двенадцать 192-битных ячеек.
`FLAG` читается из окружения только после совпадения всего вектора.

Константа EXPECTED занимает 288 байт: двенадцать последовательных значений,
каждое из шести uint32 limbs, младший limb первый. В `solve/inverse.py`
записаны эти значения после извлечения из сравнения в публичном бинаре.
Флаг в бинаре отсутствует. Локальный патч сравнения не меняет сервер.

ABC разбирается в `(voice, pitch, start, end)`. Четверть равна восьми тикам,
такт занимает 24 тика, произведение заканчивается на тике 384. На изображении
даны такты 1–5 и 12–16. В бинаре проверяются исходные времена всех нот,
аккордовые кратности, известные края и сопровождение.

Готового файла с ритмом скрипки нет. `extract.py` находит таблицу проверки
в Linux-бинаре по последовательности нот баса и фортепиано. Запись таблицы
состоит из четырёх little-endian int32: голос, высота, начало и окончание.
Перед сопровождением лежат 83 события скрипки; скрытые высоты обозначены `-1`.
Из этой таблицы получаем времена нот и известные высоты, нужные для обращения VM.

## Публикации и адресация

Ноты сопровождения публикуют высоту при завершении, на note-off.
В начале ноты скрипки VM запоминает последние завершившиеся ноты баса
и фортепиано. Публикации текущего тика уже доступны; текущие незавершённые
ноты сопровождения ещё не опубликованы. До первой публикации высота равна нулю.

Пусть `B` и `P` обозначают эти две опубликованные MIDI-высоты. Адресация:

```python
region = B % 4
pairs = [(0, 1), (1, 2), (2, 0)]
a, b = pairs[(P - B) % 3]
word = (violin_pitch - B) % 32
```

Бас выбирает одну из четырёх областей по три ячейки. Фортепиано разрешает
работу с двумя ячейками выбранной области. Скрипка задаёт пятибитное слово.
Все двенадцать ячеек изначально содержат единицу.

## Что делает скрипка

На note-off скрипки слово исполняется от старшего бита к младшему:

```python
for bit in range(4, -1, -1):
    if word >> bit & 1:
        memory[region][b] += memory[region][a]
    else:
        memory[region][a] += memory[region][b]
```

Сложение точное, переполнение вызывает fault. 

## Обращение вычисления

Большая ячейка однозначно определяет последний
бит. Вычитаем меньшую из большей и получаем предыдущее состояние.

Начинаем с EXPECTED и обходим завершения в обратном порядке, включая
известные начало и окончание мелодии. Для каждой ноты пять раз обращаем ADD.
Первый извлечённый бит является младшим битом слова:

```python
word = 0
for bit_index in range(5):
    bit = int(y > x)
    word |= bit << bit_index
    if bit:
        y -= x
    else:
        x -= y
```

Затем ищем высоту из алфавита проверки входа, для которой
`(pitch - B) % 32 == word`. Алфавит занимает интервал 57–82, его ширина
меньше 32, поэтому соответствующая высота может быть только одна.
После обращения всех 83 нот должны получиться двенадцать единиц.
Проверяем также известные края, кратности и ритм пропуска.

Все операции обратимы в положительных целых. Поэтому полного перебора
мелодий не требуется. Ограничения стека, ресурсов и сроков жизни могут
отклонить кандидат; восстановленная партия проходит их при прямом запуске.

## Получение ABC и флага

`emit.py` записывает восстановленные события с точными длительностями.
Одновременные ноты разной длины представлены наложениями через `&`.
Решатель проверяет обратное чтение ABC и равенство всех событий.

Из корня папки задания:

```sh
python3 solve/solve.py --output recovered.abc

public/lead-part-tester recovered.abc public/bass.abc public/rhythm.abc --check
```
